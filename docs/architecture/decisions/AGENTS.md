# Architecture Decision Record Instructions

Create an ADR for an accepted, durable decision that affects multiple areas, data ownership, security, deployment, or a costly migration.

- Use the next four-digit sequence and a short kebab-case filename.
- Include Status, Context, Decision, Alternatives considered, Consequences, and Revisit when.
- Keep accepted ADRs immutable except for typo or link corrections.
- To reverse a decision, add a new ADR and mark the old one superseded with a link.
- Record evidence and uncertainty honestly; do not manufacture benchmarks.
- Link every ADR from `docs/index.md`.
