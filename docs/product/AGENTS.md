# Product Documentation Instructions

Describe user problems, audiences, outcomes, scope, acceptance criteria, and measurable success. Keep implementation choices out unless they are themselves a product constraint.

- Distinguish MVP, post-MVP, and explicitly excluded work.
- Write acceptance criteria as observable behavior.
- State assumptions and adoption gates for deferred capabilities.
- Avoid claiming unverified experience, performance, traffic, or business results.
- Reconcile scope changes with `portfolio-project-plan.md` and record intentional differences.
